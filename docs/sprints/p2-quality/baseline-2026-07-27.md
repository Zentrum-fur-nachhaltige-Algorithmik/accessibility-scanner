# Sprint P2: Scanner Quality — Baseline 2026-07-27

Goal: make the scanner suite trustworthy enough to audit production sites
(first target: med-websites themes). Raw outputs in `raw/`.

## Baseline results

| Measurement | Result |
|---|---|
| vitest suite (8 files, 183 tests) | 177 passed, **3 failed**, 3 skipped — failures in mobile-specific (fixed-width-400-zoom FP still fires; 120s timeout on bad-target-size.html); 2 further errors scrolled off (unidentified, recover via per-file runs) |

| LLM smoke test (28 tests, 8 scanners, gemini-3-flash) | **28/28 — 100% detection, 0% FP** on curated corpus |

## Key insight

Per-scanner precision on curated files is now good (the April FP fixes worked),
and the LLM scanners are NOT the problem. The remaining damage is at the
**ensemble level**: running all scanners together on real pages produces
~22 violations per known-good page, plus crashes, plus a score formula that
made good pages score 0%. axe-core remains 5× faster and more precise as the
base engine — consistent with the intended architecture (library base scan +
custom scanners only where axe can't go + LLM for semantic criteria).

## Fix plan

### P0 — correctness
1. **Ensemble crashes** on good-css-background-accessible, bad-concurrent-input,
   bad-form-labels (spike marks `/ ERR`; last log before death for the css-background
   file is nontext-contrast "Testing graphical object contrast..."). Reproduce each
   individually, fix root causes. Crashes silently zero detection.
2. **mobile-specific**: fixed-width-400-zoom FP on responsive elements (computed px
   width misread as fixed — same Category-1 pattern fixed in responsive-design in
   April but not ported to phase6d-mobile-specific-scanner); 120s timeout on
   bad-target-size.html. Also identify the 2 unseen vitest failures.
3. **LLM criterion filter**: `convertViolations()` passes through any criterion the
   LLM returns; system prompt asks for restraint but no code enforces the scanner's
   wcagCriteria list. Filter off-list violations (log them as info, don't report).

### P1 — ensemble noise (the 218-on-good problem)
4. **Per-scanner noise diagnosis**: extend the spike to break down good-file
   violations by scanner id → fix the top offenders. (Good files are only
   guaranteed good for their own criterion; the fix target is scanners flagging
   things axe-core correctly ignores.)
5. **Score formula**: currently inversely correlated with page quality
   (bigger page → more FP surface → lower score; good-form-grouping: 96
   violations, score 0%). Rework: severity-weighted, deduplicated, per-criterion
   caps, calibrate so curated good-* files score ≥90.
6. **llm-focus-appearance data collection**: collects UNFOCUSED computed styles
   (outline is trivially "none" — LLM can't infer :focus state) and only finds
   inline `style="position: fixed"` (misses class-based fixed elements).
   Fix: focus elements and diff styles / parse :focus CSS rules; use
   getComputedStyle-based fixed detection.
7. **Weak prompts**: llm-behavioral (speculates about runtime behavior from static
   HTML — add concrete-evidence-only guardrails à la sensory-characteristics),
   llm-visual-presentation (judges CSS-computed properties without computed data —
   pre-compute like reading-level does).

### P2 — robustness
8. HTML truncation at 12–15k chars: long pages lose everything below the fold to
   LLM scanners. Chunk or extract per-criterion-relevant subsets.
9. Pin a stable LLM model (currently google/gemini-3-flash-preview), set
   max_tokens, keep the truncated-JSON recovery as fallback only.
10. Implement the axe-`incomplete` LLM reviewer
    (docs/issues/llm-incomplete-result-reviewer.md) — axe is the precision
    workhorse; its incomplete results are the highest-value LLM target.
