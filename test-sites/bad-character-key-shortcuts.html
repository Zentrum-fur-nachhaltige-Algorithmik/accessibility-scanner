Problematic Character Key Shortcuts (BAD)

This page demonstrates violations of WCAG 2.1.4: single character key shortcuts that cannot be remapped or disabled.

Violation 1: Single Character Navigation Shortcuts

Single character keys (j, k, n, p) are used for navigation. These cannot be disabled or remapped and conflict with screen reader browse mode where these keys type characters.

Keyboard shortcuts: j Next item · k Previous item · n Next page · p Previous page

Violation 2: Single Character Action Shortcuts

Actions are bound to single characters (s, d, r, f, e). No settings panel to remap or disable them. Speech input users may accidentally trigger actions.
From: alice@example.com

Meeting rescheduled to 3pm tomorrow. Please confirm attendance.

From: bob@example.com

Quarterly report attached for your review.

Violation 3: Accesskey Attributes with Conflicting Characters

Accesskey attributes use single characters that conflict with browser and assistive technology shortcuts. No mechanism to remap them.
Home (accesskey: h) | About (accesskey: a) | Contact (accesskey: c) | Search (accesskey: s) | Login (accesskey: l)

Use the accesskey shortcuts for quick navigation. These cannot be changed.

Violation 4: Single Character Toggle Shortcuts

Single keys toggle UI features (m for mute, t for theme, g for grid). No way to disable or reassign these bindings.

Quick toggles: m Mute · t Dark/Light theme · g Grid/List view · ? Show help
