Phase 6A Test: Non-text Contrast (WCAG 1.4.11)

🎨 Non-text Contrast Requirements

WCAG 1.4.11 Success Criteria: Non-text content must have a contrast ratio of at least 3:1 against adjacent colors for:

  • User interface components: Borders of buttons, form controls, etc.
  • Graphical objects: Parts of graphics that convey information
  • Focus indicators: Visual indication of keyboard focus
  • Interactive states: Hover, active, disabled states

Exceptions: Inactive/disabled components, logos, decorative graphics

Test both sections below - Good examples should have 3:1+ contrast, Bad examples should fail contrast requirements.

✅ GOOD: UI Components with Sufficient Contrast (3:1+)

✅ Buttons with Clear Boundaries

Border contrast: 3.8:1 against white background

Focus indicator: 4.2:1 contrast orange outline

✅ Form Controls with Visible Borders

✅ Custom Controls with Clear States

✅ Progress Indicators with Clear Boundaries

Progress bar: 4.1:1 border contrast, 3.5:1 fill boundary

✅ Interactive Controls

Slider: 4.1:1 track border, 3.1:1 thumb contrast

✅ Graphical Objects with Meaning

Chart elements: 3.5:1 border contrast to convey data meaning

❌ BAD: UI Components with Insufficient Contrast (<3:1)

❌ Buttons with Invisible Boundaries

Border contrast: 1.3:1 against white background - FAILS

Focus indicator: 1.6:1 contrast - FAILS

❌ Form Controls with Barely Visible Borders

❌ Custom Controls with Unclear States

❌ Progress Indicators Without Clear Boundaries

Progress bar: 1.02:1 border contrast, 1.1:1 fill - FAILS

❌ Interactive Controls with Poor Contrast

Slider: 1.1:1 track border, 1.05:1 thumb contrast - FAILS

❌ Icon Buttons Without Clear Boundaries

Icon buttons: 1.04:1 border, 1.3:1 icon contrast - FAILS

❌ Graphical Objects with Poor Meaning Contrast

Chart elements: 1.05:1 border contrast - meaning unclear - FAILS

🧪 Scanner Testing Guidelines

Expected Scanner Behavior:

  • Non-text Contrast Scanner (1.4.11) should detect:
    • ❌ Button borders with <3:1 contrast against background
    • ❌ Form control borders with insufficient contrast
    • ❌ Focus indicators with <3:1 contrast
    • ❌ Interactive element states with unclear contrast
    • ❌ Graphical objects conveying information with poor contrast
    • ❌ Progress bars, sliders, toggles with unclear boundaries
    • ❌ Chart elements, icons where contrast affects meaning
    • ✅ All UI components with 3:1+ contrast ratios
    • ✅ Clear visual boundaries on interactive elements
    • ✅ Sufficient focus indicator contrast

Contrast Calculation Examples:

  • Good button border: #4a90e2 on #ffffff = 3.8:1 ✅
  • Bad button border: #e9ecef on #ffffff = 1.3:1 ❌
  • Good focus outline: #ff6b35 on #ffffff = 4.2:1 ✅
  • Bad focus outline: #ced4da on #ffffff = 1.6:1 ❌

Testing Procedure:

  1. Identify all user interface components on page
  2. Extract border colors and background colors
  3. Calculate contrast ratios for all component boundaries
  4. Test interactive states (hover, focus, active, disabled)
  5. Check graphical objects that convey information
  6. Verify 3:1 minimum contrast requirement
  7. Generate violations for elements below threshold

Success Criteria:

PASS: All non-text elements have 3:1+ contrast against adjacent colors

FAIL: Any meaningful UI component or graphical object below 3:1 contrast

Edge Cases to Handle:

  • Gradients: Test multiple points along gradient
  • Complex backgrounds: Test against average or dominant color
  • Disabled states: Often exempt from requirements
  • Decorative elements: Not required to meet contrast
  • Logos: Exempt from non-text contrast requirements
