Phase 6A Test: Label in Name (WCAG 2.5.3)

🎤 Label in Name Requirements

WCAG 2.5.3 Success Criteria: For user interface components with labels that include text or images of text, the accessible name contains the text that is presented visually.

Critical for: Voice control software (Dragon NaturallySpeaking, Voice Control, etc.)

How it works: Users say the visible text to activate controls. If accessible name doesn't match, commands fail.

Test scenarios:

  • User sees "Submit" button, says "Click Submit" - should work
  • User sees "Search" but accessible name is "Find" - command fails
  • User sees "Next Page" but accessible name is "Continue" - command fails

🧪 Scanner Testing Guidelines

Expected Scanner Behavior:

  • Label in Name Scanner (2.5.3) should detect:
    • ❌ Buttons where visible text doesn't match accessible name
    • ❌ Form controls where label text isn't contained in accessible name
    • ❌ Links where visible text differs from accessible name
    • ❌ Image buttons where alt text doesn't match visible text
    • ❌ Complex controls with misleading accessible names
    • ❌ Language mismatches between visual and accessible names
    • ✅ All controls where accessible name contains visible text
    • ✅ Proper matching between visual labels and programmatic names

Algorithm Steps:

  1. Extract visible text: Get text content visible to sighted users
  2. Get accessible name: Calculate accessible name using accessibility API
  3. Normalize text: Remove extra whitespace, convert to lowercase
  4. Check containment: Verify visible text is contained in accessible name
  5. Handle special cases: Icons, images, complex widgets
  6. Report violations: Elements where check fails

Text Extraction Rules:

  • Buttons: Text content, excluding screen-reader-only text
  • Form labels: Associated label text or visible placeholder
  • Links: Link text content
  • Images: Text overlays or captions when present
  • Complex widgets: Primary visible identifier text

Accessible Name Calculation:

  • aria-label: Takes precedence over other methods
  • aria-labelledby: Referenced element(s) text content
  • Form elements: Associated label element
  • Buttons: Text content or aria-label
  • Images: Alt attribute value
  • Fallbacks: Title, text content as last resort

Edge Cases to Handle:

  • Punctuation: Ignore differences in punctuation
  • Case sensitivity: Perform case-insensitive comparison
  • Extra spaces: Normalize whitespace before comparison
  • Icon fonts: Ignore decorative icon characters
  • Abbreviations: "Info" vs "Information" should flag violation
  • Translations: Same language required for match

Success Criteria:

PASS: Visible text is contained within accessible name (case-insensitive)

FAIL: Visible text is not found in accessible name

Voice Control Testing:

Users with voice control software should be able to activate any control by speaking its visible text. Test commands:

  • "Click [button text]"
  • "Press [button text]"
  • "Tap [button text]"
  • "Select [option text]"
  • "Choose [link text]"
