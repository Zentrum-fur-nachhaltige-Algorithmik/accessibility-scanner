Test: Keyboard Native Override Violations (BAD)

WCAG 2.1.1 Verletzungen: Native, tastaturbedienbare Elemente werden durch JavaScript oder tabindex="-1" unzugänglich gemacht

VIOLATION 1: Native Buttons mit tabindex="-1" deaktiviert

Problem: Funktionierende Buttons werden durch tabindex="-1" für Tastaturnutzer unzugänglich

❌ Diese Buttons sind nur per Maus erreichbar, nicht über Tab-Navigation

VIOLATION 2: Links mit onclick und tabindex="-1"

Problem: Navigation-Links werden durch tabindex="-1" für Tastaturnutzer unzugänglich

Zur Startseite

Produktübersicht

Kontakt

❌ Navigation nur per Maus möglich, Enter-Taste funktioniert nicht

VIOLATION 3: Formular-Inputs durch tabindex="-1" unzugänglich

Problem: Wichtige Eingabefelder werden für Tastaturnutzer unzugänglich gemacht

❌ Formularfelder können nicht per Tab-Taste erreicht werden

Problem: Native Select durch Custom Dropdown ersetzt, aber ohne Tastaturunterstützung

VIOLATION 10: Datei-Upload ohne Tastaturzugriff

Problem: Native File Input versteckt und durch nicht-zugänglichen Button ersetzt

Keine Datei ausgewählt

❌ File Upload nur per Maus möglich, Enter öffnet keinen Dialog

Warum das problematisch ist

WCAG 2.1.1 Verstöße - Keyboard Accessibility:

  • ❌ tabindex="-1" macht natürlich erreichbare Elemente unzugänglich
  • ❌ Custom Controls ohne Tastaturunterstützung brechen native Funktionalität
  • ❌ Wichtige Formularelemente werden für Tastaturnutzer unsichtbar
  • ❌ Navigation und Interaktion nur noch per Maus möglich
  • ❌ Screen Reader verlieren Zugang zu wichtigen Kontrollen
  • ❌ Native semantische Bedeutung geht verloren

Betroffene Benutzergruppen:

  • 👥 Tastatur-only Nutzer: Können Elemente nicht erreichen oder bedienen
  • 👥 Screen Reader-Nutzer: Verlieren Zugang zu wichtigen Kontrollen
  • 👥 Motorische Einschränkungen: Müssen mühsam zwischen Eingabemethoden wechseln
  • 👥 Kognitive Beeinträchtigungen: Verlieren gewohnte Interaktionsmuster
  • 👥 Power-User: Können nicht effizient nur mit Tastatur arbeiten
